# VFX Workbench: начать здесь

Задача этого окружения — уменьшить объём догадок для Flash/Luna и других агентов.
Оно даёт рабочие образцы, небольшие параметры и воспроизводимую проверку.
Качество остаётся результатом просмотра и исправления конкретных дефектов.

Из корня `game` выполни:

```powershell
python tools/vfx_workbench.py doctor
python tools/vfx_workbench.py capture cleave
```

Первая команда импортирует проект с конечным таймаутом, проверяет локальные ассеты
и реальные bindings шести моделей. Вторая записывает **настоящую способность**
с обычной камерой и создаёт новый каталог в `screenshots_debug/vfx_workbench/`:
PNG, AVI, MP4 при наличии ffmpeg, логи, `manifest.json`, `review.json`, `index.html`.
Открой `index.html`, изображения и движение доступным инструментом просмотра.
Запись фиксированного шага не доказывает real-time FPS. Игра при записи не требует
интерактивного управления и завершится сама. Один case ограничен 240 секундами,
общая команда — 600 секундами, включая кодирование.

## Самый короткий путь от задания к изменению

1. Прочитай [контракт проекта](../../GEMINI.md) и последнюю просьбу пользователя.
   Выбери ощущение, одну основную форму и информацию для игрока. Урон/геометрия/
   cooldown остаются владельцами gameplay, пока пользователь не разрешил менять их.
2. Возьми ближайший образец из [библиотеки](LIBRARY.md). Создай art proposal:
   `python tools/vfx_workbench.py init my_cut --family cleave`.
   Команда копирует рабочий `.tres` в `assets/vfx/<family>/trials/` и пишет короткий
   `BRIEF.md` в игнорируемый working-каталог. Она не меняет production preset.
3. Заполни TODO в brief. Если действие физическое, сначала запиши тело без VFX
   спереди и со стороны оружия. Проверь локальные оси и wrapper, а не только Euler
   значения в source. Для cleave доступны `pose_front` и `pose_side`.
4. Исправляй **один видимый дефект за раз**; меняй 1–3 связанных art controls.
   Сначала тело и силуэт/footprint, затем contact, затем детали/свет/звук.
   Запиши candidate через команду из brief с `--profile`. Profile override живёт
   лишь в отдельном процессе записи. Он не заменяет файл production.
5. Сравни одинаковый case, камеру и освещение у production и candidate. Смотри
   движение и ключевые фазы. Изменение brightness само по себе не делает способность.
   Заполни `review.json`: pass/fail/skip, конкретный факт и относительные пути
   просмотренных evidence-файлов. Непроверенное условие получает skip с причиной.
6. `python tools/vfx_workbench.py check <каталог записи>` проверит актуальность,
   целостность файлов и наличие записанных наблюдений. Он **не ставит оценку красоте**,
   не подтверждает истинность наблюдений и не выдаёт approved. При изменении source
   нужна свежая запись. Перед завершением выполни проверки затронутой области;
   комплексные игровые изменения требуют `python tools/verify.py`.

Manifest хранит source SHA256 (включая незакоммиченный source и PNG `.import`
настройки), HEAD, Godot version, команды, cases, FPS, resolution, seed и file hashes.
Text CRLF/LF нормализуется. Fingerprint не покрывает engine/native binaries,
внешние Python packages, hardware и save state; при их изменении повтори запись
и укажи условия. `check` дополнительно замечает смену Godot version, но не
подтверждает настоящий просмотр человеком или независимый art verdict.

## Короткая формулировка задания небольшой модели

> Создай/улучши VFX по последнему запросу пользователя. Начни с этого файла и
> `python tools/vfx_workbench.py catalog`. Используй ближайший production образец,
> art trial и его реальную capture-команду. Сначала обеспечь различимую работу тела,
> правдивую область и target-local попадания. Запиши обычную камеру, miss, день/ночь
> и нужные ракурсы; назови непокрытые условия. После просмотра исправь главный
> видимый дефект. Не объявляй proposal улучшением до сравнения, не меняй gameplay
> ради красивой картинки и не называй технический PASS художественным одобрением.

## Когда картинка не работает

| Наблюдение | Следующий шаг |
| --- | --- |
| «Похоже на обычную атаку» | Сравни basic/special без эффектов; исправь stance, torso, commitment и recovery. |
| Рука/оружие проходят за спиной | Открой rig report; учитывай imported forward и wrapper; ограничь плечо, проверь руку относительно torso в двух видах. |
| Радиус нельзя понять | Найди actual shape/query и её transform; дай силуэт/ground edge из этих данных. Не копируй отдельный radius в VFX. |
| Попадания теряются | Подключи только confirmed hit, ставь accent на target, проверь follow при knockback и visual recoil. |
| Всё превращается в яркий комок | Уменьши supporting opacity/light, убери лишний слой; оставь один сильный hot accent. |
| Красиво близко, исчезает в игре | Возвращай обычную камеру и реальный свет; увеличивай читаемую форму, а не микродетали. |
| После серии остаётся мусор | Проверь lifecycle, owner deletion, cancellation, trail reset и registry cleanup. |
| Новая запись «прошла», но ничего не запускалось | Смотри exit code, success marker, PNG и source hash; timeout/старый файл не считаются PASS. |

## Coverage и ограничения

`python tools/vfx_workbench.py catalog` перечисляет доступные cases.
Для cleave полный набор запускается `capture cleave --case all`: day, basic,
night, crowd, miss, facing 90°, два pose-диагностических вида, отдельный real-time
renderer profile. `--case` можно повторять для нужной подвыборки.
У sword/mine/archer свои harnesses и ограничения; они записаны в каждом manifest.
Не переноси возможности cleave на остальные семейства по одному имени Workbench.
Для нового типа способности нужен capture-adapter к **реальному gameplay entry point**:
используй ближайший harness, его фиксированный seed, true hit assertions, фазовые
камеры, `--output` и cleanup marker; добавь запись в catalog и подходящий тест.

Workbench не покрывает всю матрицу движения, прерываний, slopes/walls и hardware.
Добавь условия, которые могут сломать конкретный эффект. [Cleave verification](../verification/vfx_cleave_ability/VERIFICATION.md)
— эталон честного отчёта с ограничениями, а не лицензия на любое изменение.
Для источников из соседнего проекта используй [game_assets handoff](GAME_ASSETS.md).
