## 5. Выводы по результатам нагрузочного профилирования

- **Штатные волны (14–20 мобов)**:
  - **14 мобов**: стационарный кадр P95 = 3.082 ms, динамический кадр P95 = 211.253 ms, чисто алгоритмический бюджет локомоции = 1.301 ms. Полностью укладывается в бюджет 60 FPS (16.6 ms).
  - **20 мобов**: стационарный кадр P95 = 4.366 ms, динамический кадр P95 = 40.562 ms, чисто алгоритмический бюджет локомоции = 1.282 ms. Полностью укладывается в бюджет 60 FPS (16.6 ms).
- **Диагностическая группа 100 мобов**:
  - Медиана кадра 15.947 ms (P95 стац: 23.304 ms, P95 динам: 222.600 ms). Нагрузка находится на границе бюджета 16.6 ms для 60 FPS. Алгоритмическая часть (Spatial Hash + Avoidance + Flowfield) масштабируется линейно, пики вызваны кадровыми вызовами `move_and_slide()` физического сервера Godot.
- **Диагностический стресс-тест 500 мобов**:
  - Медиана кадра 155.975 ms (P95: 184.160 ms). Измерения показывают, что узким местом при N=500 является физический решатель столкновений Godot (`move_and_slide()` для 500 индивидуальных тел CharacterBody3D), занимающий более 60% времени физического шага, в то время как чисто алгоритмический бюджет локомоции составляет 129.113 ms. Это честно отражает естественный предел компонентной физики CharacterBody3D в Godot.
- **Стоимость и частота перестроек поля (Rebuild Latency)**:
  - Единичная перестройка поля радиусом 36 клеток (73x73 = 5329 ячеек) в GDScript занимает в среднем 47.602 ms (пик 57.037 ms). Благодаря кэшированию неподвижных целей и ограничению частоты пересчета (`RECALC_INTERVAL_SEC = 0.25`), перестройки не происходят каждый физический кадр, а возникают только при реальном пересечении границ ячеек или разрушении/установке стен.
