# Игровая песочница

Отдельная плоская арена для ручной игры и проверки существующих механик.
Используются сцена игрока, его обычный ввод, физика, изометрическая `CameraFollow`,
HUD, ресурсы, строительство и настоящие обработчики урона. Это игровая сцена;
[просмотр способностей](ABILITY_LAB.md) остаётся отдельным инструментом демонстраций.

## Запуск и управление

```powershell
python tools/run_gameplay_sandbox.py
python tools/run_gameplay_sandbox.py --smoke
```

Сцена: [gameplay_sandbox.tscn](../scenes/tools/gameplay_sandbox.tscn).
Из главного меню доступна кнопка песочницы. При прямом запуске сцены SaveManager
распознаёт её путь до загрузки профиля; Python launcher также задаёт изолированный
профиль через окружение до запуска Autoload. Обычный профиль игры не используется
для экспериментов и восстанавливается в памяти после выхода в меню.

- WASD — обычное перемещение; мышь или стрелки — направление прицеливания.
- ЛКМ/J — основная атака; ПКМ/K — спецумение; Space — рывок; Q/L — утилита;
  F — ультимейт; Tab — строительство; удержание E — взаимодействие.
- F2 или кнопка «Арена» открывает настройку и ставит бой на паузу. «Продолжить»
  возвращает управление после отпускания кнопки мыши.

Доступны Воин, существующие версии Лучника и Инженера. Песочница не меняет состав
персонажей обычного прохождения. Для Воина можно выбрать любую комбинацию девяти
талантов, включая все одновременно, и вводить произвольные неотрицательные ранги
специализаций без ограничения. Дополнительные свойства появляются с нужными
талантами; сочетания выводятся из игровой сборки. Стандартный предел шести талантов
остаётся только в обычном забеге. Постоянные бонусы открытий по умолчанию отключены;
отдельный переключатель включает бонусы девяти открытых талантов в профиле арены.

Спавн добавляет выбранных настоящих монстров и боссов перед персонажем. Количество
и дистанцию можно изменить; точка проверяется игровой проверкой коллизий и опоры.
На арене используется плоская навигация с границами, совпадающими с полом.
«Удалить врагов» удаляет их снаряды и эффекты; «Сбросить бой» пересоздаёт игроков,
постройки и временные способности с выбранной конфигурацией. Смерть происходит
обычным образом, открывает панель и позволяет возродиться без потери настоящего
героя. Автоматических волн, эвакуации и сохранения результата забега здесь нет.

Обычные убийства дают игровой XP и уровни; победа над производственным боссом
даёт уровень через `PlayerProgression`. Через панель можно добавить ресурсы или
ресурсные объекты, а затем пользоваться обычным кошельком и строительством.
Дневное и ночное освещение переключается вручную.

## Изоляция и проверки

`GameplaySandboxSession.begin()` сохраняет прежние данные SaveManager, каталог
хранения, флаги RosterManager и навигационные callbacks; повторный вход не заменяет
исходный снимок. Сессия перенаправляет хранение в `user://gameplay_sandbox/profile/`
до изменения данных песочницы. При выходе `leave()` восстанавливает исходное
состояние; обычный RunCoordinator и его смерть/эвакуация не подключаются.

Launcher проверяет готовность за 30 секунд; интерактивная игра после этого
продолжает работать в собственном процессе. `--smoke` ограничен 120 кадрами и
общим deadline 35 секунд. Лог: `.review_loop/gameplay-sandbox-run.log`.
Каноническая общая проверка — `python tools/verify.py`; отдельные проверки
песочницы проверяют изоляцию, конфигурацию, нативные сцены и очистку жизненного цикла.
Автоматическая проверка не является оценкой баланса или художественным approval.

Дополнительный конечный сценарий проходит из настоящего меню в арену, подаёт
обычные `Input` команды движения и способностей всех трёх существующих классов,
проверяет спавн каждого из 19 вариантов, живой AI, смерть/сброс и восстановление
исходного профиля в памяти и на диске:

```powershell
python tools/verify_gameplay_sandbox.py
python tools/verify_gameplay_sandbox.py --capture --movie --ffmpeg <path-to-ffmpeg>
```

Сценарий использует отдельный профиль до загрузки Autoload. Общий deadline 195 с,
внутренний watchdog 120 с; PNG/MP4 и manifest находятся в
`screenshots_debug/sandbox/`. Цели проверки оружия неподвижны, проверка
навигации использует обычного активного монстра. Прохождение и баланс таким
сценарием не измеряются; клики строительства и добыча ресурсов не входят в него.
