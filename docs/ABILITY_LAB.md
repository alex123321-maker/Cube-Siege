# Просмотр способностей Cube Siege

Просмотрщик показывает **реальные умения трёх классов**, их свойства, влияние
реализованных карт и состояний, попадания и фактическое здоровье. Создания,
редактирования, добавления и сохранения способностей в интерфейсе нет.

Во всех демонстрациях используется игровая модель **Воина**, в том числе для
выстрела Лучника и турели Инженера. Класс игрового обработчика при этом сохраняется.
Цели используют сцену **зомби**, её анимации, hurtbox, здоровье, отбрасывание и
оглушение. Запас 1000 HP нужен только для демонстрации. Награды не выдаются.

## Запуск

```powershell
python tools/run_ability_lab.py
```

Либо **Project → Tools → Просмотр способностей** в Godot, либо F6 для сцены
`scenes/tools/ability_lab.tscn`. Имя файла и команда сохранены для совместимости.
Запуск проверяет готовность за 30 секунд и сообщает PID и путь журнала.
Профиль просмотра изолирован от обычного сохранения игры.

## Использование

1. Выберите класс и умение слева. Для каждого класса доступны базовая атака,
   спецумение, утилита, ультимейт и рывок. Сохранены 15 прежних записей; для Воина
   добавлены девять работающих талантов и три диагностические комбинации.
2. Выберите готовый вариант: базовый, применимая карта, состояние дуэли,
   успешное парирование или установка с подрывом мины.
3. Справа показаны свойства и пояснения. Если вариант меняет значение,
   отображается **база → результат**. Значения доступны только для чтения.
4. Нажмите **Показать / повторить**. Сцена сбросится, и игровой обработчик
   применит способность. В журнале появятся фактические события урона.
5. **Сбросить сцену** возвращает исходную постановку и отменяет отложенные
   действия старой демонстрации. Переключение способности делает то же самое.

Мина в варианте подрыва получает два обычных применения с интервалом 1 секунду.
Для успешного парирования зомби выполняет настоящий удар через 0.2 секунды после
защитной стойки. Орбитальный удар получает фиксированную точку арены; в игре
по-прежнему используется обычное наведение курсором. Дуэль и приманка используют
игровое переназначение целей. Зомби не атакуют автоматически, кроме явно заданного
сценария парирования. Ремонт зданий молотом описан в карточке, но отдельной
повреждённой постройки в этой постановке нет.

Время демонстрации идёт в реальном времени. Способности, таймеры, снаряды,
отбрасывание и анимации работают через обычный цикл Godot. Ручной вызов физики
из интерфейса, отдельный исполнитель способностей и подмена спецслота игрока
не используются.

## Источники свойств и ограничения

- Урон, здоровье и параметры движения читаются из настоящего игрока.
- Перезарядки, подготовка, множители, парирование и орбитальный удар используют
  общие константы игровых обработчиков. Числа и баланс при выделении констант
  не изменены.
- Параметры турели, мины и приманки читаются из игровых сцен.
- Карты применяются через `PlayerAbilities.apply_card_upgrade`; каталог не
  вычисляет их эффекты вторым независимым набором правил.
- Мастерство профиля не применяется: показаны базовые свойства и один выбранный
  вариант. Игровой прогресс не меняется.
- Девять талантов Воина и три комбинации используют `WarriorTalentRuntime`,
  `PlayerCombat`, `PlayerHealth` и `PlayerMovement` из обычной игры. Вихрь
  поражает круговую область; с выпадом область перемещается вместе с Воином
  всё активное окно. Попадание в одну цель ограничено одним за применение.
- Сброс удаляет выбранные таланты, специализации, накопленный Триумф, мораль,
  регенерацию, замедления и журнал попаданий рывка. Постоянные бонусы профиля
  не применяются. Зомби в диагностической сцене не выдают опыт и ресурсы.
- Сейчас «Око снайпера» включает состояние и меняет камеру; прибавка дальности
  стрел из GDD не подключена. Карточка явно сообщает это ограничение.
- Лечение «Закалённого клинка» начисляется в обработчике фактического урона
  здоровью. Урон щиту, избыточный урон и отражение не дают лечение. Ответный
  удар парирования лечит только с комбинацией «Закалка кровью».
- Прежние карты остались диагностическими вариантами старого каталога.
  В первой версии забега вместо карт используются таланты и специализации.

## Проверка и кадры

```powershell
python tools/verify.py
python tools/run_ability_lab.py --smoke
python tools/run_ability_lab.py --capture --entry 1 --delay 0.3
python tools/run_ability_lab.py --capture --entry 6 --delay 0.4
python tools/run_ability_lab.py --capture --entry 13 --delay 1.3
python tools/run_ability_lab.py --capture --entry 21 --delay 0.4
```

Индексы: 0–4 — Воин, 5–9 — Лучник, 10–14 — Инженер; порядок у каждого класса:
атака, спецумение, утилита, ультимейт, рывок. 15–23 — таланты в порядке
`WarriorTalentCatalog.TALENT_IDS`, 24–26 — диагностические комбинации.
Кадр сохраняется в
`.review_loop/ability-laboratory.png`. Это изображение самого Godot.

Набор `tests/integration/test_ability_viewer.gd` проверяет весь каталог и модели,
отсутствие редактирования, соответствие свойств реальному урону, карты,
парирование, снаряды, турель, мину, орбитальный удар, состояния, рывок, сброс
отложенных действий и сохранность ожидающей обычной атаки при нажатии спецатаки
на перезарядке. Результаты: [отчёт проверки](verification/ability_lab/README.md).
