# Отчёт о физической и динамической приёмке (Issue #43)

## 1. Физическая приёмка формы чанка (`PhysicsDirectSpaceState3D`)

В тесте `tests/unit/test_chunk_builder.gd::test_chunk_terrain_physics_direct_space_state_raycasts_and_collision()` форма `result["shape"]`, возвращённая генератором `ChunkBuilder.build_chunk_terrain(0, 0, 1337)`, помещена в активное физическое пространство `World3D` через `StaticBody3D` и `CollisionShape3D`:

1. **Верхняя поверхность (Ground Surface)**:
   - Запрос сверху вниз на клетке `(0, 0)`: луч из `(0.5, h + 3.0, 0.5)` в `(0.5, h - 3.0, 0.5)`.
   - Результат: точка попадания `Y = h`, нормаль `(0, 1, 0)` (`dot(Vector3.UP) > 0.99`).

2. **Боковые грани снаружи по четырём направлениям (Compass Directions)**:
   - **North (-Z)**: луч извне `(wx+0.5, y_mid, wz - 0.6)` в `(wx+0.5, y_mid, wz + 0.6)`. Попадание с нормалью `(0, 0, -1)` (`dot > 0.99`).
   - **South (+Z)**: луч извне `(wx+0.5, y_mid, wz + 1.6)` в `(wx+0.5, y_mid, wz + 0.4)`. Попадание с нормалью `(0, 0, 1)` (`dot > 0.99`).
   - **West (-X)**: луч извне `(wx - 0.6, y_mid, wz + 0.5)` в `(wx + 0.6, y_mid, wz + 0.5)`. Попадание с нормалью `(-1, 0, 0)` (`dot > 0.99`).
   - **East (+X)**: луч извне `(wx + 1.6, y_mid, wz + 0.5)` в `(wx + 0.4, y_mid, wz + 0.5)`. Попадание с нормалью `(1, 0, 0)` (`dot > 0.99`).

3. **Правила проходимости (Traversability)**:
   - Ступень в 1 блок (`(7, 1)` y=1 vs `(6, 1)` y=0): луч на высоте `y = 0.5` сталкивается со стенкой; луч на высоте `y = 1.1` (над уступом) свободно проходит без коллизии.
   - Стена $\ge 2$м (`(8, 2)` y=3 vs `(7, 2)` y=1): луч на 1-м метре (`y = 1.5`) сталкивается со стенкой; луч на 2-м метре (`y = 2.5`) также сталкивается со стенкой (непроходимая стена).

## 2. Интеграционная проверка двух полос генератора (`build_chunk_terrain`)

В тесте `tests/unit/test_chunk_builder.gd::test_chunk_builder_build_chunk_terrain_tall_cliff_splits_two_band_surfaces()`:
- Проверен реальный меш от `build_chunk_terrain(0, 0, 1337)` на высоком уступе `(8, 2)` y=3 $\to$ запад `(7, 2)` y=1 (перепад 2м).
- Верхний метр (`Y` в диапазоне `[2.0, 3.0]`): сгенерирован на поверхности соответствующего биома с нормалью `(-1, 0, 0)` и UV `v` в `[-3.0, -2.0]`.
- Нижний метр (`Y` в диапазоне `[1.0, 2.0]`): сгенерирован на отдельной поверхности материала скал `mat_cliff` с нормалью `(-1, 0, 0)` и UV `v` в `[-2.0, -1.0]`.

## 3. Динамическая геймплейная приёмка и стриминг чанков

Сценарий `tools/capture_issue_43_terrain.gd` со штатной игровой камерой (`CameraFollow`), освещением дня и физической обработкой игрока (`CharacterBody3D`):
- **Единый владелец физики (Single Physics Owner)**: Вся локомоция управляется исключительно через штатную систему ввода (`Input.action_press("move_up")`) и компонент `PlayerMovement`. Никаких вспомогательных вызовов `player.move_and_slide()` или `_apply_gravity_and_step_up()` из тестового цикла нет.
- **Ступень 1м**: 
  - Начальная позиция: `(5.50, 0.90, 1.50)` (клетка `(5, 1)` y=0).
  - Игрок движется на восток под управлением штатного шага физики, автоматически срабатывает воксельный step-up assist.
  - Итоговая позиция на вершине уступа `(7, 1)`: `(8.60, 2.90, 1.50)`.
  - Фактический подъём по высоте: `+2.00m`, статус `is_on_floor() == true`.
- **Стена 2м (непроходимый утес)**:
  - Начальная позиция: `(7.20, 1.90, 2.50)` (клетка `(7, 2)` y=1).
  - Плоскость стены утеса клетки `(8, 2)` y=3 расположена на `x = 8.0`.
  - При непрерывном движении на восток игрок упирается в коллизию стены и останавливается на `x = 7.60` (`< 8.0`), `y = 1.90`, `is_on_floor() == true`. Игрок не проваливается сквозь стену и не запрыгивает на 2-метровый обрыв.
- **Непрерывный проход через границу чанков (`x = 16.0`)**:
  - Игрок начинает на `(13.0, 5.90, 1.50)` в чанке `(0, 0)`.
  - Непрерывным ходом движется на восток через границу чанка `x = 16.0` и переходит в чанк `(1, 0)` до координаты `x = 18.20`.
  - Переход абсолютно бесшовный: геометрия и коллизия монолитны, щели и мерцания отсутствуют.
- **Штатный рантайм стриминг чанков (`MapGenerator._process`)**:
  - Использованы стандартные продакшен-радиусы: `load_radius_chunks = 3`, `unload_radius_chunks = 5` без ручных форсированных вызовов `update_player_chunks(..., true)`.
  - Стриминг и дозагрузка происходят через штатную многокадровую асинхронную очередь `pending_load_chunks` со скоростью `max_chunk_loads_per_frame = 1`.
  - Контрольный чанк: `(0, 0)`.
  - Игрок непрерывным ходом движется на восток по коридору $z = 1.5$ в чанк `(6, 0)` ($x \ge 96.0$, фактически $x = 96.60$, дистанция $dx = 6 > unload\_radius\_chunks$).
  - Штатный `MapGenerator._process` зафиксировал смену чанка игрока на `(6, 0)` и выгрузил контрольный чанк `(0, 0)`: `map_gen.active_chunks.has(Vector2i(0, 0)) == false`. Зафиксировано телеметрией `[DYNAMIC-STREAMING-UNLOAD]` и скриншотом `dyn_06_chunk_unloaded.png`.
  - Затем игрок непрерывным ходом движется на запад обратно в сторону базы. При входе в чанк `(3, 0)` ($x \le 64.0$, фактически $x = 62.80$, дистанция $dx = 3 \le load\_radius\_chunks$) штатный `MapGenerator._process` поставил чанк `(0, 0)` в очередь и загрузил его через `pending_load_chunks`: `map_gen.active_chunks.has(Vector2i(0, 0)) == true`. Зафиксировано телеметрией `[DYNAMIC-STREAMING-RELOAD]` и скриншотом `dyn_07_chunk_reloaded.png`.
  - Игрок непрерывно возвращается в контрольный чанк `(0, 0)` через границу $x = 16.0$ до $x = 14.87$, `is_on_floor() == true`. Все стыки чанков монолитны, щели и мерцания отсутствуют.
- **Последовательная запись движения (Dynamic Animated GIF)**:
  - Зафиксировано 135 непрерывных отрендеренных кадров игрового процесса во время всех фаз локомоции и стриминга.
  - Собрана оптимизированная анимация `terrain_dynamic_walk_streaming.gif` (4.9 MB, 68 кадров с шагом 2 и акцентом на ключевых моментах, размер укладывается в лимит GitHub 10 МБ). Анимация наглядно демонстрирует: преодоление 1м ступени, остановку перед 2м утесом, переход границы чанка, дальний переход с выгрузкой чанка `(0, 0)` штатным `_process`, обратный путь с прогрессивной дозагрузкой чанка `(0, 0)` и возвращение на базу.
