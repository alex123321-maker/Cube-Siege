# In-Run Talents, Specializations and Hidden Synergies — Design Concept

> **Статус:** текущий согласованный design concept, НЕ implementation contract.
>
> **Назначение:** зафиксировать текущую модель построения билда внутри одного забега.
>
> **Приоритет:** если старые документы описывают внутризабеговую прокачку иначе, этот документ отражает более новое согласованное направление. Точные числа, частота наград и финальный баланс пока не зафиксированы.

## 1. Цель системы

Внутризабеговая прокачка должна давать игроку не набор случайных процентов, а возможность осознанно строить стиль игры.

Система разделяет четыре разных понятия:

1. **Базовая способность** — уже существующая часть набора героя: базовая атака, специальная способность, рывок/мобильность, классовая утилита, ультимативная способность и т. п.
2. **Талант** — добавляет новую механику, преобразует существующую механику или заметно меняет способ применения способности.
3. **Специализация** — усиливает уже существующее свойство способности. Специализация не должна сама создавать новую механику.
4. **Скрытая синергия** — автоматически появляется, когда игрок в одном забеге получает конкретную пару талантов. Она может создавать новую механику и не требует отдельного выбора.

Ключевое разделение:

```text
новая механика / существенное преобразование
→ талант

усиление уже существующего свойства
→ специализация

неожиданное взаимодействие двух талантов
→ скрытая синергия
```

## 2. Таланты

### 2.1. Максимум

Текущий концепт: в одном забеге герой может иметь **до 6 талантов**.

Это максимум, а не обязательная цель.

Игрок может сознательно закончить забег с меньшим числом талантов, если предпочитает вложить больше развития в существующие способности.

### 2.2. Что должен делать талант

Талант должен:

- добавлять новое поведение;
- преобразовывать существующее поведение;
- менять тактическое применение способности;
- либо создавать достаточно выраженный новый игровой паттерн.

Талант **не обязан** просто повышать общую силу персонажа.

Нежелательный дизайн:

```text
+5% общего урона
+7% скорости движения
+10 HP
```

если эти значения существуют как самостоятельные карточки без связи с конкретной механикой.

Числовые изменения допустимы внутри таланта, если они являются частью его конкретной механики.

## 3. Специализации принадлежат способностям

Специализации **не закреплены жёстко за талантами**.

Каждая базовая способность имеет собственный набор специализируемых свойств.

Пример для Рассечения:

```text
Рассечение
├─ радиус
├─ урон
└─ перезарядка
```

Игрок может развивать эти свойства независимо от того, взят ли конкретный талант на Рассечение.

### 3.1. Почему это важно

Если базовая способность уже имеет полезное свойство, оно должно быть доступно для развития без необходимости создавать талант, который искусственно дублирует эту механику.

Пример: если Дуэль уже даёт снижение входящего урона или отражение части урона, эти параметры могут быть базовыми специализациями Дуэли.

Не требуется отдельный талант вида «Дуэль теперь снижает входящий урон», если способность уже делает это по базовому контракту.

## 4. Таланты могут расширять пул специализаций

Если талант добавляет способности новое свойство, которое можно масштабировать без создания новой механики, талант может открыть новую специализацию этой способности.

Пример:

```text
Базовое Рассечение:
- радиус
- урон
- перезарядка

Талант «Широкий выпад»:
- добавляет выпад
- после получения таланта может появиться
  специализация дальности выпада

Талант «Вихревое рассечение»:
- превращает атаку в круговую
- базовая специализация радиуса продолжает работать
  и на новой форме атаки
- если у вращения появляется масштабируемое существующее
  свойство, оно может добавить ещё одну специализацию
```

### 4.1. Нет требования симметрии

У разных способностей и талантов может быть разное число доступных специализаций.

Это нормально.

- у одной способности может быть 3 подходящих направления;
- у другой — 5;
- талант может не открыть ни одной новой специализации;
- другой талант может открыть 1–2 дополнительных направления.

Не нужно искусственно придумывать свойства только ради одинакового количества вариантов.

## 5. Специализация не создаёт новый эффект

Главное ограничение:

> Специализация усиливает только то, что уже существует в текущей версии способности.

Допустимо:

- больше радиус;
- больше урон;
- меньше перезарядка;
- больше длительность;
- больше число уже существующих целей;
- сильнее уже существующее лечение;
- больше дальность уже существующего выпада.

Недопустимо как специализация:

- «атака теперь вызывает молнию»;
- «рывок теперь взрывается»;
- «парирование теперь лечит», если до этого лечения вообще не было.

Это уже территория талантов или скрытых синергий.

## 6. Количество и ранги специализаций

Система не должна быть жёстко привязана к формуле:

```text
6 талантов × 3 специализации
```

Текущий концепт предполагает **расширяемый пул специализаций способностей**.

В будущем, если забеги окажутся слишком короткими по развитию, можно:

- добавить новые специализируемые свойства;
- увеличить количество рангов существующих специализаций;
- добавить новые специализации через новые таланты.

Это должно происходить без изменения базовой архитектуры системы.

Точные caps отдельных специализаций пока не утверждены.

## 7. Как игрок получает специализации

Специализация должна быть **направленным вложением**, а не случайным выбором способности.

Нежелательный вариант:

```text
игрок строит билд вокруг Рассечения,
но игра предлагает только:
- Дуэль
- Парирование
- Базовую атаку
```

Это создаёт не тактический выбор, а принудительную трату очка в ненужное направление.

Предпочтительная модель:

```text
СПЕЦИАЛИЗИРОВАТЬ
        ↓
игрок выбирает способность
        ↓
игрок выбирает доступное свойство этой способности
```

Рандом должен в основном определять **какие новые таланты предлагаются**, а игрок должен иметь высокий контроль над тем, **куда вкладывать глубину билда**.

## 8. Talent Checkpoint и «Сосредоточиться»

Текущий концепт разделяет обычное развитие и моменты выбора новой механики.

В определённые моменты забега игрок получает **Talent Checkpoint**.

На нём предлагается:

```text
1 из нескольких случайных талантов
ИЛИ
СОСРЕДОТОЧИТЬСЯ
```

### «Сосредоточиться»

Игрок отказывается от нового таланта и вместо этого получает несколько очков специализации для уже существующего билда.

Рабочая стартовая гипотеза:

```text
1 талант
vs
примерно 2 очка специализации
```

Это **не финальный баланс**, а текущая модель, которая делает отказ от нового таланта реальным стратегическим вариантом.

Точный обменный курс будет определяться playtest.

## 9. Широкий и узкий билд

Система должна поддерживать оба подхода.

### Широкий билд

```text
больше талантов
→ больше разных механик
→ больше потенциальных комбинаций
→ больше шансов открыть скрытые синергии
```

### Узкий билд

```text
меньше талантов
→ меньше разных механик
→ больше вложений в специализации
→ значительно более развитые ключевые способности
```

Поэтому 6 талантов — не обязательная оптимальная стратегия.

Баланс Talent Checkpoint / Focus должен быть настроен так, чтобы оба типа билда были жизнеспособны.

## 10. Скрытые синергии

Синергии — отдельный слой открытия и эксперимента.

### Правила

Синергия:

- привязана к конкретной паре талантов;
- **не показывается игроку заранее**;
- не является карточкой;
- не занимает talent slot;
- не требует specialization point;
- не требует отдельного подтверждения;
- автоматически активируется, когда оба необходимых таланта получены в одном забеге;
- может создавать новую механику, в отличие от специализации.

Пример:

```text
Контратака
+
Закалённый клинок
        ↓
ЗАКАЛКА КРОВЬЮ
```

Как только второй необходимый талант получен, синергия включается автоматически.

### Reveal

При первом срабатывании условия игрок должен получить понятное событие открытия:

```text
СИНЕРГИЯ ОБНАРУЖЕНА
ЗАКАЛКА КРОВЬЮ
```

После открытия HUD может визуально показать связь между соответствующими талантами.

До открытия конкретная синергия не должна быть раскрыта игроку.

## 11. Generic stat upgrades

Отдельные внутризабеговые карточки общего вида:

- +N% общий урон;
- +N% общая скорость;
- +N максимум HP;

не являются частью текущего целевого дизайна.

Если числовой параметр улучшается, предпочтительно чтобы он относился к конкретной способности, таланту или уже существующему эффекту.

## 12. Пример: Рассечение

Базовая способность:

```text
Рассечение
- конус атаки
- радиус
- урон
- cooldown
```

Базовые специализации могут развивать:

```text
радиус
урон
cooldown
```

### Без талантов

Игрок может увеличить радиус обычного конусного Рассечения.

### После «Вихревого рассечения»

Способность становится круговой.

Та же специализация радиуса теперь увеличивает радиус круговой атаки.

Игроку не нужен отдельный «радиус Вихревого рассечения», если речь идёт об одном и том же базовом свойстве способности.

### После «Широкого выпада»

Появляется новое свойство — длина выпада.

Если это свойство является масштабируемым, оно может появиться в пуле специализаций Рассечения.

## 13. Пример: Дуэль

Если базовая Дуэль уже имеет:

- бонус/модификатор входящего урона;
- отражение урона;
- другие собственные числовые параметры;

они могут быть доступны как базовые specialization axes Дуэли.

Талантам не нужно дублировать эти свойства только ради возможности их улучшать.

## 14. Следствия для HUD

HUD должен в будущем различать минимум два слоя:

### Talents

Показывают:

- какие новые механики собраны в текущем забеге;
- сколько из 6 talent slots занято;
- открытые синергии после их обнаружения.

### Abilities / Specializations

Показывают:

- куда вложено развитие базовых способностей;
- какие свойства усилены;
- какие дополнительные specialization axes открылись благодаря талантам.

Не требуется одновременно выводить полный список всех specialization properties на основном gameplay HUD.

Точный UI ещё не утверждён.

## 15. Что уже считается согласованным

- максимум 6 талантов в текущем концепте;
- игрок не обязан заполнять все 6 slots;
- специализации относятся прежде всего к способностям, а не к талантам;
- базовые способности имеют собственные специализации;
- талант может открыть дополнительные специализации;
- число специализаций не обязано быть одинаковым;
- специализация не создаёт новую механику;
- generic passive stat cards не являются целевым направлением;
- специализация должна быть направленным вложением игрока, а не случайным выбором способности;
- на Talent Checkpoint можно отказаться от нового таланта ради большего количества specialization investment;
- широкие и узкие билды должны быть жизнеспособны;
- синергии скрыты до получения обоих талантов;
- синергии активируются автоматически и бесплатны.

## 16. Что пока НЕ решено

Следующие детали требуют дальнейшего design/playtest решения:

- точное число волн/длина забега;
- частота Talent Checkpoints;
- сколько талантов предлагается на Talent Checkpoint;
- финальный обменный курс «талант ↔ Focus specialization points»;
- caps/ranks конкретных специализаций;
- максимальное число specialization points за забег;
- правила reroll;
- возможность respec внутри забега;
- сохраняется ли информация об уже обнаруженных синергиях между забегами в энциклопедии/мета-UI;
- точная форма отображения талантов, специализаций и обнаруженных синергий на HUD;
- точный reward schedule между волнами.

Эти пункты не должны самостоятельно определяться implementation agent.
