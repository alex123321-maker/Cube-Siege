# Медиа в комментарии PR

Это обязательный шаг для Gemini / Antigravity и Codex при визуальных изменениях. Агент сам загружает медиа отдельным комментарием PR; отдельное согласование в рамках задачи не требуется. Это разрешённое исключение из запрета собственных reviews и статусных комментариев.

Правило применяется к UI, моделям, сценам, анимациям, VFX и изменениям видимого поведения игры: атакам, попаданиям, парированию, рывку. Изменение только скриптов не освобождает от медиа, если меняется наблюдаемое поведение. Для изменений только документации или иных задач без видимого результата медиа не требуются.

GitHub-коннектор может возвращать пустое содержимое PNG из репозитория; поэтому файлы в `review/`, ссылки на `blob`/`raw` и картинки в описании PR не заменяют загруженные вложения в комментарии.

## Порядок действий

1. До создания PR прочитай эту инструкцию и подготовь медиа. Создай PR через обязательный `tools/review_loop/create_pr.py`. После создания и каждого push исправлений подготовь пакет для актуального HEAD PR. Проверь, что локальный HEAD совпадает с опубликованным head SHA; получай доказательства на коде и ресурсах этого коммита, без посторонних незакоммиченных изменений. Временные скриншоты/записи не требуется коммитить только ради загрузки.
2. Проверь `gh pr comment --help`: должен поддерживаться `--attach`. При отсутствии флага сообщи о необходимости обновления gh; не подменяй загрузку ссылками на локальные файлы. Для загрузки нужен push-доступ к репозиторию.
3. Включи применимые к задаче исходные утверждённые references, обязательные ракурсы затронутых ассетов, игровой вид, сравнение семейства и кадры важных анимаций/VFX. Для изменения поведения покажи изменённый сценарий в игре или Ability Lab; для анимаций/VFX приложи доступную короткую запись. Подпиши назначение каждого файла. Для mockup явно укажи, что это не проверка рендера движка. Не уменьшай детали до нечитаемости ради одного листа.
4. Сохрани UTF-8 Markdown тела комментария во временный файл, например `.review_loop/visual-media-comment.md` (каталог игнорируется Git). Укажи полный SHA, список изменённых ассетов/сценариев, пути файлов и ограничения. В самом конце тела добавь точный маркер `<!-- agent:review-loop -->`, чтобы watcher не принял публикацию за внешнее замечание.
5. Для изображения используй `![описание](относительный/путь.png)`; для видео — `![](относительный/путь.mp4)` отдельным абзацем. Передай каждый тот же путь через отдельный `--attach`: gh заменит ссылки на загруженные вложения на месте, сохранив маркер в конце. Укажи ссылку в теле для каждого вложения, иначе gh допишет его после маркера. Не более 50 вложений за вызов; большие пакеты дели на несколько подписанных комментариев с тем же SHA и маркером. Изображения/GIF — до 10 MB; видео — до 10 MB на бесплатном плане GitHub, больший лимит проверяй по документации и доступу. Для скриншотов используй PNG, для видео — MP4/MOV/WebM; WebP preview экспортируй в поддерживаемый формат.
6. Ограничь команду загрузки общим timeout по [OPERATION_TIMEOUTS.md](OPERATION_TIMEOUTS.md). Проверь успешное завершение, прочитай опубликованный комментарий, убедись, что локальные пути заменены URL вложений и изображения открываются, видео воспроизводится, а маркер остался в конце. Сохрани URL комментария в отчёте текущего чата. Публикация не означает, что внешний reviewer уже просмотрел медиа или одобрил качество.
7. При изменении визуального результата загрузи свежие медиа. Для нового SHA без визуальных изменений можно приложить те же проверенные файлы и явно указать это. Не дублируй уже опубликованный полный пакет для того же SHA. После неоднозначной сетевой ошибки сначала проверь наличие комментария, затем решай, нужна ли повторная публикация.

## Пример тела комментария

Замени SHA, сценарий и пути на данные текущей задачи. Если видео нет, убери его абзац и соответствующий `--attach`.

```markdown
Медиа для коммита <полный head SHA PR>.

Сценарий: <изменённый ассет или поведение>.
Ограничения: <что не удалось проверить, либо «нет»>.

![Игровой вид](review/gameplay.png)

Запись изменённого сценария:

![](review/gameplay.mp4)

<!-- agent:review-loop -->
```

## Пример команды для существующего PR

Из корня текущего репозитория, после подготовки тела с медиа и маркером:

```powershell
gh pr comment <pr-number> --repo <owner/repository> --body-file .review_loop/visual-media-comment.md --attach review/gameplay.png --attach review/gameplay.mp4
```

Номер PR, репозиторий и файлы подставляй по текущей задаче. Команда публикует отдельный комментарий с вложениями. Создание PR по-прежнему выполняется через wrapper; самостоятельное review/approval запрещено.

## Критерий завершения

PR с визуальными изменениями и его review fixes не готовы, пока медиа для актуального SHA не опубликованы и не проверены. В итоговом отчёте обязателен URL комментария. Если запись, загрузка или проверка вложений недоступна, сообщи конкретную ошибку и невыполненный шаг. Не объявляй визуальную передачу выполненной и не заменяй независимую оценку самооценкой из `visual_review.json`.

Документация: [загрузка через GitHub CLI](https://docs.github.com/en/github-cli/github-cli/attaching-files-with-github-cli), [форматы и лимиты GitHub](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files).
