# Визуальные вложения в PR

Агент сам передаёт изображения внешнему reviewer через комментарий PR. Доступа к чату reviewer не требуется. GitHub-коннектор может возвращать пустое содержимое PNG из репозитория; поэтому файлы в `review/` и ссылки на `blob`/`raw` не заменяют загруженные вложения.

## Порядок действий

1. Создай PR через обязательный `tools/review_loop/create_pr.py`. После создания и каждого push исправлений подготовь пакет для актуального HEAD PR. Проверь, что локальный HEAD совпадает с опубликованным head SHA и прикладываемые файлы соответствуют этому коммиту. Не прикладывай незакоммиченные рендеры как доказательство опубликованного SHA.
2. Проверь `gh pr comment --help`: должен поддерживаться `--attach` (локально проверено на gh 2.101.0). При отсутствии флага сообщи о необходимости обновления gh; не подменяй загрузку ссылками на локальные файлы.
3. Включи исходные утверждённые references, обязательные ракурсы затронутых ассетов, игровой вид, сравнение семейства и кадры важных анимаций/VFX. Подпиши назначение каждого изображения. Для mockup явно укажи, что это не проверка рендера движка. Не уменьшай детали до нечитаемости ради одного листа.
4. Сохрани UTF-8 Markdown тела комментария во временный файл, например `.review_loop/visual-media-comment.md` (каталог игнорируется Git). Укажи полный SHA, список ассетов, пути файлов и ограничения. В самом конце тела добавь точный маркер `<!-- agent:review-loop -->`, чтобы watcher не принял публикацию за внешнее замечание.
5. В теле используй `![описание](относительный/путь.png)` для каждого файла и передай тот же путь через отдельный `--attach`. gh заменит эти ссылки на загруженные вложения на месте, сохранив маркер в конце. Не более 50 вложений за вызов; большие пакеты дели на несколько подписанных комментариев с тем же SHA и маркером. PNG должен укладываться в ограничение GitHub для изображения (10 MB).
6. Проверь успешное завершение команды, прочитай опубликованный комментарий, убедись, что локальные пути заменены URL вложений и изображения открываются. Сохрани URL комментария в отчёте текущего чата Antigravity. Публикация не означает, что внешний reviewer уже просмотрел изображения или одобрил качество.
7. При изменении визуального результата загрузи свежие изображения. Для нового SHA без визуальных изменений можно приложить те же проверенные файлы и явно указать это. Не дублируй уже опубликованный полный пакет для того же SHA. После неоднозначной сетевой ошибки сначала проверь наличие комментария, затем решай, нужна ли повторная публикация.

## Пример для существующего PR

Из корня репозитория, после подготовки тела с изображением и маркером:

```powershell
gh pr comment 16 --repo alex123321-maker/assets --body-file .review_loop/visual-media-comment.md --attach assets/characters/references/family_lineup_front.png
```

Номер PR, репозиторий и файлы подставляй по текущей задаче. `gh pr comment` разрешён только для этого пакета визуальных доказательств; создание PR по-прежнему выполняется через wrapper, самостоятельное review/approval запрещено.

Если загрузка или проверка вложений недоступна, сообщи конкретную ошибку. Не объявляй визуальную передачу выполненной и не заменяй независимую оценку самооценкой из `visual_review.json`.

Документация: https://docs.github.com/en/github-cli/github-cli/attaching-files-with-github-cli
