# Workflow: /review-ready

Финальный аудит готовности задачи к Pull Request.

## Пошаговый сценарий

### Шаг 1: Полный цикл сборки и тестов
1. Запустить единую команду верификации проекта:
   ```bash
   python tools/verify.py
   ```
2. Убедиться, что:
   - Все зависимости на месте;
   - Нативный C++ собран без предупреждений;
   - Godot импортирует проект чисто;
   - Тесты GUT завершаются с кодом 0;
   - Дымовой запуск проходит без падений.

### Шаг 2: Аудит здоровья проекта (Project Health)
1. Проверить скрипты на синтаксические ошибки:
   ```bash
   godot --headless --editor --quit
   ```
2. Убедиться в отсутствии циклических зависимостей ресурсов и сломанных связей.

### Шаг 3: Автоматическое формирование чек-листа Acceptance Criteria
Сформировать статус по каждому критерию из Issue:
```markdown
### Acceptance Criteria Checklist
- [x] AC 1: Описание — проверено тестом `test_name.gd`
- [x] AC 2: Описание — подтверждено в runtime
- [ ] AC 3: Описание — НЕ проверено (указать причину)
```
> [!CAUTION]
> Запрещено отмечать непроверенные критерии как выполненные.

### Шаг 4: Аудит Git Diff и гигиены репозитория
1. Проверить `git status` и `git diff`:
   - Нет ли файлов вне скоупа задачи;
   - Не изменены ли дизайнерские константы (урон, кулдауны);
   - Нет ли временных файлов (`.tmp`, отладочные логи, лишние скриншоты);
   - Не создано ли случайных битых файлов.
2. Проверить актуальность `docs/STATUS.md` при добавлении новых подсистем.

### Шаг 5: Формирование компактного PR-отчёта
Подготовить компактный отчёт с:
- Ссылкой `Closes #N` / `Fixes #N`;
- Кратким описанием изменений;
- Чек-листом критериев приёмки;
- Таблицей проверок (Что проверено / Как проверено / Статус);
- Скриншотами (при визуальных правках);
- Известными ограничениями и рисками.
