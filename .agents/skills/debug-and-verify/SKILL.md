# Debug & Verify Skill

Руководство по локализации, исправлению ошибок и сбору доказательств работоспособности.

## Главное правило
**Никогда не объявлять баг исправленным только на основании чтения исходного кода.**
Исправление должно быть подтверждено практическим воспроизведением.

## Порядок действий при исправлении бага

1. **Воспроизведение до исправления (Reproduce)**:
   - Прочитать Bug Issue (Current vs Expected behavior, Reproduction steps).
   - Запустить игру или тестовый сценарий и лично воспроизвести проблему.
   - Зафиксировать свидетельства (ошибка в консоли, скриншот, стек вызовов).
2. **Локализация первопричины (Root Cause)**:
   - Найти непосредственную причину сбоя, а не маскировать симптомы `if not null`.
3. **Регрессионный тест (Regression Test)**:
   - Добавить модульный или интеграционный тест в `tests/`, который падает на текущем баге.
4. **Минимальное исправление (Minimal Fix)**:
   - Внести точечное исправление, не затрагивая посторонние подсистемы.
5. **Повторное воспроизведение (Confirm Fix)**:
   - Повторить первоначальный сценарий воспроизведения. Убедиться, что бага больше нет.
   - Проверить, что добавленный регрессионный тест теперь проходит успешно.
6. **Контроль регрессий в проекте**:
   - Запустить общий набор тестов `python tools/verify.py`.
   - Просмотреть итоговый `git diff` на отсутствие случайных правок.
