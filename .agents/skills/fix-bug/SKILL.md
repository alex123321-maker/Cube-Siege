# Workflow: /fix-bug

Процедура локализации и устранения дефектов с обязательным подтверждением воспроизведением.

## Пошаговый сценарий

### Шаг 1: Контракт дефекта
1. Получить Bug Issue (`gh issue view <number>`).
2. Зафиксировать:
   - Фактическое поведение (Current behavior);
   - Ожидаемое поведение (Expected behavior);
   - Шаги воспроизведения (Reproduction steps);
   - Критерии приёмки (Acceptance criteria).

### Шаг 2: Воспроизведение и сбор доказательств
1. Запустить игру или тестовый сценарий.
2. Воспроизвести баг до любых правок кода.
3. Зафиксировать вывод логов, стек трейс или скриншот ошибки.

### Шаг 3: Регрессионный тест
1. Добавить автоматический тест в `tests/unit/` или `tests/integration/`, падающий при воспроизведении ошибки.

### Шаг 4: Локализация первопричины и минимальное исправление
1. Создать ветку `fix/<issue-number>-<slug>`.
2. Найти причину бага и применить точечный фикс.
3. Не выполнять попутный рефакторинг не связанных участков.

### Шаг 5: Повторное воспроизведение и верификация
1. Запустить добавленный регрессионный тест (он обязан пройти).
2. Повторить шаги ручного воспроизведения (баг не должен проявляться).
3. Запустить полный цикл проверки:
   ```bash
   python tools/verify.py
   ```

### Шаг 6: PR и отчёт
1. Просмотреть `git diff`.
2. Оформить PR с `Fixes #N` и чек-листом Acceptance Criteria.
