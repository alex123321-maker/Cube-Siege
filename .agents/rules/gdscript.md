# GDScript Architecture & Quality Rules

Правила для разработки и изменения скриптов (`scripts/**/*.gd`):

## 1. Строгая типизация и регистрация классов
- **Typed GDScript**: Все новые функции, аргументы, возвращаемые значения и экспортируемые переменные обязаны иметь явную статическую типизацию (`var speed: float = 5.0`, `func take_damage(amount: int) -> void:`).
- **`class_name`**: Объявлять `class_name` для всех сущностей, участвующих в межсистемном взаимодействии или служащих базовыми классами (например, `EnemyBase`, `BuildingBase`).
- Избегать нетипизированных `Dictionary` для передачи структурированных доменных данных — предпочитать `Resource` или легковесные типизированные классы.

## 2. Слабая связанность и отсутствие Stringly-Typed API
- Запрещено полагаться на строковые вызовы через `has_method("...")`, `get("...")` или `call("...")` для базовых контрактов игрового процесса. Использовать явные методы типизированных интерфейсов или сигналы.
- Запрещено использовать `find_child("...")` или `get_node("../../../...")` в качестве Dependency Injection. Передавать зависимости явно через инициализацию (`setup(...)`), сигналы или экспортируемые ссылки (`@export var target: Node3D`).
- Прямые ссылки через `@onready var` допустимы **только внутри собственного поддерева сцены** (scene subtree).

## 3. Разделение UI и Gameplay State
- **UI не владеет состоянием**: HUD, модальные окна и полосы здоровья лишь отображают данные и передают команды игрока через сигналы/EventBus.
- **Геймплей не ищет UI**: Игровые контроллеры, враги и строения не должны напрямую искать `Label`, `ProgressBar` или `Control` и менять их свойства. Вся коммуникация — через события в `EventBus` (`EventBus.player_health_changed.emit(...)`).

## 4. Производительность в Physics/Process Loop
- **Никаких `get_nodes_in_group` в `_physics_process`**: Поиск узлов по группе в каждом кадре создаёт аллокации и просадки FPS. Использовать реестры, пространственные триггеры (`Area3D`) или подписку на события появления/уничтожения.
- Избегать создания и уничтожения сотен временных объектов (`instantiate()` / `queue_free()`) в горячем цикле без пулинга.

## 5. Запрет на God Objects
- Не раздувать существующие контроллеры (такие как `player_prototype.gd`) новой логикой, если её можно выделить в отдельный компонент (например, оружие, управление строительством, баффы).
- Соблюдать принцип единственной ответственности: контроллер управляет вводом и движением, боевая система — атаками и уроном, инвентарь/крафт — ресурсами.
