# C++ GDExtension Rules

Правила для разработки и изменения нативного C++ ядра (`src/**/*.cpp`, `src/**/*.h`):

## 1. Область применения C++
- C++ GDExtension в проекте Cube Siege используется **только для утверждённых высокопроизводительных систем**:
  - 2D Flowfield Pathfinding (волновой алгоритм Дейкстры для сотен мобов);
  - Массовая симуляция толпы (Swarm simulation & MultiMesh updates);
  - Пулы сотен снарядов (Projectiles pool);
  - Подтверждённые профайлером узкие места (hot paths).
- Не переносить стандартную логику способностей, квестов, инвентаря или UI в C++.

## 2. Безопасность памяти и стандарты C++
- **RAII**: Все ресурсы и память должны освобождаться автоматически.
- **Const Correctness**: Все геттеры, неизменяемые ссылки и параметры методов обязаны быть помечены `const`.
- **Никакого неявного владения сырыми указателями (Raw Ownership)**: Использовать ссылки Godot (`Ref<T>`) или стандартные умные указатели (`std::unique_ptr`, `std::shared_ptr`). Сырые указатели допустимы только для заимствования без владения.
- **Изоляция констант геймплея**: Числовые параметры баланса (скорость, радиусы, урон) не должны быть захардкожены внутри C++. Они обязаны экспортироваться в Godot через `ClassDB::bind_method` и свойства (`ADD_PROPERTY`), чтобы оставаться настраиваемыми в редакторе Godot и скриптах.

## 3. Регистрация в Godot и ABI
- Каждый экспортируемый класс обязан наследоваться от соответствующего класса Godot и регистрироваться в `src/register_types.cpp` через `GDREGISTER_CLASS(ClassName)`.
- Публичный интерфейс C++ ↔ Godot должен быть минимальным, стабильным и документированным.

## 4. Сборка и форматирование
- Любое изменение файлов в `src/` требует обязательной локальной пересборки:
  ```bash
  scons custom_api_file=extension_api.json platform=windows target=template_debug -j4
  ```
- Код должен форматироваться в соответствии с корневым файлом `.clang-format`.
