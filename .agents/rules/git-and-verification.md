# Git and Verification Standards

Правила версионирования, чистоты репозитория и проверки качества:

## 1. Ветки и коммиты
- **Одна логическая задача = одна ветка**: Разработка ведётся в ветках формата:
  - `feat/N-short-description` (для новой функциональности);
  - `fix/N-short-description` (для исправления багов);
  - `chore/N-short-description` (для инфраструктуры и сборки).
- Запрещено работать напрямую в ветке `main`.
- Коммиты должны быть небольшими, атомарными и с осмысленными сообщениями в Conventional Commits (`feat:`, `fix:`, `test:`, `chore:`).
- Каждый коммит обязан оставлять проект в компилируемом и рабочем состоянии.

## 2. Разделение форматирования и логики
- Запрещено объединять массовое автоформатирование файлов с функциональными изменениями кода.
- Форматирование существующего кода, при необходимости, выполняется отдельным изолированным коммитом.

## 3. Чистота репозитория (No Junk)
- Запрещено коммитить:
  - Кэши (`.godot/`, `.sconsign.dblite`, `__pycache__/`);
  - Скомпилированные динамические библиотеки (`bin/*.dll`, `bin/*.so`);
  - Временные файлы отладки и скриншоты (`*.tmp`, отладочные дампы);
  - Локальные настройки с абсолютными путями конкретной машины.

## 4. Обязательный аудит перед завершением
- Перед объявлением задачи завершённой инженер обязан просмотреть полный `git diff`:
  ```bash
  git diff
  git status --short
  ```
- Убедиться, что не осталось случайных правок, забытых `print("DEBUG")` и непредусмотренных изменений файлов.
